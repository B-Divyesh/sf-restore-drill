Postgres restore rehearsal

Prove your Postgres backup restores.

For small self-hosted teams that need recovery proof before an outage.

Try it with sample dataReplays a recorded sample restore and opens its signed report.
  • Runs with your local Docker engine
  • Sample files stay in a temporary directory
  • MIT-licensed command-line tool

How the command works

Rehearse a restore in four steps.

  1. 01

    Create an isolated Docker network.

    The command uses a new internal network for the rehearsal.

  2. 02

    Restore a shipped sample backup.

    The demo uses a SQL file with three sample orders in a temporary directory.

  3. 03

    Check the restored data.

    The sample confirms that all three orders are present after the restore.

  4. 04

    Sign the report and remove test resources.

    Keep the report path printed by the command for later inspection.

Start for real

Install one binary on your Docker host.

Read the configuration before you run a drill against your own backup.

git clone https://github.com/B-Divyesh/sf-restore-drill.git
cd sf-restore-drill
cargo install --locked --path crates/restore-drill
restore-drill demo

What this does not do

It rehearses a restore. It does not restore production.

Use a copied backup and a Docker host you control. Read the privacy policy for site and command data handling.
